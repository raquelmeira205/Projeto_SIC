# Project Requirements vs Implementation Analysis

## Executive Summary

This document provides a comprehensive analysis of the SIC IoT Ad-hoc Network project, comparing the requirements from the project specification (PDF) against the current implementation.

---

## ✅ Implemented Features

### 1. **Topology & Network Structure** ✅

#### Tree Topology
- ✅ **Implemented**: Nodes maintain uplink/downlink structure
- ✅ **Hop Count**: Tracked and advertised in BLE manufacturer data
- ✅ **Uplink Selection**: Nodes choose uplink with lowest hop count
- ✅ **Lazy Approach**: Nodes don't switch uplinks unless connection is lost
- ✅ **Negative Hop Count**: Disconnected nodes advertise hop=-1 (0xFF)

**Files**: `node/ble_manager.py`, `node/router.py`

---

### 2. **Addressing & Routing** ✅

#### NID-based Addressing
- ✅ **128-bit NIDs**: Implemented and extracted from X.509 certificates
- ✅ **Forwarding Tables**: Router maintains NID → connection mapping
- ✅ **Learning**: Routes learned from incoming packets (switch-like behavior)
- ✅ **Packet Structure**: Source NID, Dest NID, Type, Payload

**Files**: `common/packet_structs.py`, `node/router.py`, `common/pki_utils.py`

---

### 3. **Network Liveness (Heartbeat)** ✅

#### Heartbeat Protocol
- ✅ **Sink Broadcasts**: Heartbeat sent every 5 seconds
- ✅ **Sequence Numbers**: Incremental counter in each heartbeat
- ✅ **Signature**: Heartbeats signed by Sink
- ✅ **Verification**: Nodes verify signature before forwarding
- ✅ **Downlink Forwarding**: Heartbeats forwarded to all downlinks
- ⚠️ **Timeout Detection**: Implemented but using MockSecurity (not real verification)

**Files**: `sink/heartbeat_service.py`, `node/router.py`, `common/packet_headers.py`

**Issue**: Currently uses `MockSecurity.verify_sink_signature()` which always returns `True`

---

### 4. **Security - PKI & Certificates** ✅

#### Certificate Infrastructure
- ✅ **CA Implementation**: Certificate Authority for issuing certs
- ✅ **X.509 Certificates**: Using P-521 elliptic curve
- ✅ **NID in Certificate**: NID stored in SERIAL_NUMBER field of Subject
- ✅ **Sink Identification**: Sink cert has "Sink" in OU field
- ✅ **Certificate Verification**: Code to verify cert signatures

**Files**: `support/gen_certs.py`, `common/pki_utils.py`, `common/certificate_parser.py`

---

### 5. **Security - Authentication & Key Exchange** ✅

#### Security Handshake
- ✅ **Certificate Exchange**: Mutual cert exchange implemented
- ✅ **Certificate Verification**: Verify peer cert with CA
- ✅ **Ephemeral Keys**: ECDH ephemeral key generation (P-521)
- ✅ **Key Signing**: Ephemeral keys signed with long-term private key
- ✅ **Session Key Derivation**: ECDH + HKDF-SHA256 → 32-byte session key
- ✅ **Unit Tests**: Full handshake tested in `testes/test_handshake.py`

**Files**: `common/security_handshake.py`, `common/security_primitives.py`

**Issue**: ⚠️ **NOT INTEGRATED** - Handshake exists but is not triggered on BLE connection

---

### 6. **Security - Link Layer Protection** ✅

#### Hop-by-Hop Security
- ✅ **HMAC-SHA256**: 32-byte MAC for integrity
- ✅ **Sequence Numbers**: 4-byte counter for replay protection
- ✅ **Replay Detection**: Tracks last valid seq per connection
- ✅ **Packet Structure**: Includes seq_num and MAC fields
- ✅ **Key Storage**: Router maintains per-link session keys

**Files**: `common/crypto_utils.py`, `node/router.py`, `common/packet_structs.py`

**Issue**: ⚠️ Currently uses `DEFAULT_TEST_KEY` instead of handshake-derived keys

---

### 7. **BLE Communication** ✅

#### Bluetooth Low Energy
- ✅ **BLE Advertisements**: Custom manufacturer data (ID 0xFFFE)
- ✅ **Advertisement Payload**: Hop count + NID (17 bytes)
- ✅ **GATT Server**: Service UUID + RX characteristic
- ✅ **Connection Management**: Connect/disconnect to devices
- ✅ **Packet Transmission**: Send/receive via GATT characteristic
- ✅ **Device Discovery**: Scan for nearby devices (simplepyble)

**Files**: `common/bluez_classes.py`, `node/ble_manager.py`, `node/ble_discovery.py`

**Recent Fix**: ✅ Advertisement size reduced to <31 bytes (removed LocalName)

---

### 8. **User Interface** ✅

#### CLI Interface (Recently Implemented)
- ✅ **Device NID**: Displayed on startup
- ✅ **Uplink Status**: Shows connected/disconnected + uplink NID
- ✅ **Hop Count**: Displayed in status
- ✅ **Forwarding Table**: Shows entries (though currently empty in testing)
- ✅ **Manual Controls**: `scan`, `connect`, `status`, `stats`
- ✅ **Send Messages**: `send <message>` command
- ⚠️ **Downlinks List**: Not explicitly shown in UI
- ⚠️ **Lost Heartbeats**: Not shown in UI
- ⚠️ **Routed Messages Count**: Not shown in UI

**Files**: `node/cli_ui.py`

**Note**: Old curses UI (`node/node_ui.py`) and tkinter UI (`node/ui.py`) still exist but are not used

---

## ❌ Missing / Incomplete Features

### 1. **Security Integration** ❌ **CRITICAL**

#### Handshake Trigger
- ❌ **NOT IMPLEMENTED**: Security handshake not triggered on BLE connection
- ❌ **Using Mock Keys**: Router uses `DEFAULT_TEST_KEY` instead of session keys
- ❌ **MockSecurity**: Both node and sink use `MockSecurity` stub

**Required Action**:
1. Trigger `SecurityHandshake.perform_handshake()` after BLE connection
2. Store derived session key in `router.link_keys[connection]`
3. Replace `MockSecurity` with real signature verification

**Impact**: **HIGH** - Core security requirement not functional

---

### 2. **DTLS End-to-End Protection** ❌ **CRITICAL**

#### End-to-End Security
- ❌ **NOT IMPLEMENTED**: No DTLS between IoT devices and Sink
- ❌ **Service Identification**: No service name/client ID mechanism
- ❌ **Inbox Service**: Not implemented

**Required from Spec**:
- DTLS protection for end-to-end communication
- Service identified by name ("Inbox")
- Clients identified by random number (like transport port)
- Router daemon wraps/unwraps DTLS traffic

**Impact**: **HIGH** - Major project requirement missing

---

### 3. **Network Controls** ⚠️ **PARTIAL**

#### Required Controls
- ✅ **Search nearby devices**: Implemented (`scan` command)
- ✅ **Connect to device**: Implemented (`connect` command)
- ❌ **Stop heartbeat to specific device**: NOT IMPLEMENTED

**Missing**: Command to simulate broken link by stopping heartbeat to a downlink

**Impact**: **MEDIUM** - Debugging feature for demonstrations

---

### 4. **UI Information Display** ⚠️ **PARTIAL**

#### Missing from UI
- ❌ **Downlinks List**: Not displayed
- ❌ **Downlink NIDs**: Not shown
- ❌ **Lost Heartbeat Count**: Not tracked/displayed
- ❌ **Routed Messages Count**: Not tracked/displayed

**Impact**: **LOW** - UI completeness for demonstrations

---

### 5. **Sink Inbox Service** ❌

#### Application Service
- ❌ **Inbox Service**: Not implemented
- ❌ **Message Display**: Sink doesn't show received messages with sender NID
- ❌ **Service Naming**: No service identification mechanism

**Impact**: **MEDIUM** - Application layer functionality

---

### 6. **Heartbeat Timeout Chain Reaction** ⚠️ **PARTIAL**

#### Uplink Loss Handling
- ✅ **Timeout Detection**: Implemented (3 missed heartbeats)
- ✅ **Uplink Disconnect**: Node disconnects from uplink
- ❌ **Downlink Cascade**: Node should disconnect ALL downlinks when losing uplink
- ❌ **Chain Reaction**: Sub-tree disconnection not fully implemented

**Impact**: **MEDIUM** - Network resilience behavior
